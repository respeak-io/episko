# Maintenance

> Rules and their reasons, compressed. Trust the code over the docs when they disagree, and fix the doc in the same commit.

The fleet home stage gets a **Maintenance** view beside **Activity**, and the project dashboard gets **Today | Maintenance** tabs. Both answer one question per project: what is rotting while nobody looks. The answer is spread over seven **facets**, and every facet can be fed by any CI, any security reporter, any update bot or any forge. The whole feature is built so that a new vendor is one manifest row and one Rust read function, and that a vendor nobody has written an adapter for yet says *can't check (Woodpecker)* instead of looking healthy.

## The model

- **Seven facets, fixed and closed**, always in this order: `ci`, `security`, `deps`, `release`, `git`, `prod`, `work`. A card draws all seven in fixed positions, so the eye learns where CI is.
- **A source is one adapter for one facet**: `github-actions`, `gitlab-ci`, `dependabot-alerts`, `renovate-prs`, `git-tags`, `osv`… A facet has any number of sources, and several may apply to one project at once (Dependabot *and* `cargo audit`). A facet cell is the merge of its sources' reports.
- **A marker is a source we can recognise but not read yet** (a `Jenkinsfile`, `.woodpecker.yml`, `.snyk`). It exists so the cell says *can't check (Jenkins)* rather than *no CI*. Promoting a marker to a source is the normal way the feature grows.
- **Rust reads facts; TypeScript decides.** Rust detects what applies, runs the read, normalises the vendor's vocabulary (`MODERATE` → `medium`, `timed_out` → `fail`; that is a fact, and the raw value is kept beside it) and returns a typed coverage. Whether that is *failing 1d*, *drifting* or *needs you*, and in what order cards stand, is `maint.ts`'s. Thresholds are data a team can override, never constants in Rust (the `health.rs`/`health.ts` split).
- **The frontend never names a vendor.** GitHub Actions, GitLab CI and Woodpecker all arrive as `CiRuns`; a cell, a finding and a brief are written against the fact shape. `provider-contract.test.ts`'s rule, one level over: a feature gated on a vendor id is a feature the next vendor silently lacks.

## Coverage: unknown is never green

Every report carries a `Coverage`, and only `ok` carries facts.

| state | means | example |
|---|---|---|
| `ok` | read; facts follow (possibly empty) | 3 workflows, one failing |
| `off` | the feature is switched off on the forge | Dependabot alerts disabled; code scanning "no analysis found" |
| `noAccess` | we could not see it, with a `fix` | token lacks `security_events` → `gh auth refresh -h github.com -s security_events` |
| `noTool` | the CLI it needs is missing or not logged in, with a `fix` | `glab` not installed; `cargo-audit` absent |
| `unsupported` | detected, cannot be answered | no default branch known; GitLab vulnerabilities need Ultimate |
| `notRun` | a click-only source nobody has clicked on this machine | `npm audit`, prod URL check |
| `error` | anything else, the reason verbatim | |

`facetCell` resolves a cell top-down, and **only the last step can draw the grey dot**:

1. `[maintenance] off` names the facet → *not tracked*, muted.
2. Not detected yet, or a read still out → *unread*: `—` / a skeleton, never a dot (`dirtyTag`'s three states).
3. No source and no marker → *none*, phrased per facet: *no CI*, *no update bot*, *no release*, *no deploy*.
4. Markers only → *can't check (X)*, the tip naming what was found.
5. Sources, none `ok` → *can't check*, said as its reason and never bare: the most actionable coverage (`COV_RANK`: `noAccess`, `noTool`, which carry a fix, then `off`, `error`, `unsupported`, `notRun`) names the cell in `whyWord`'s few words (*token scope*, *no access*, *signed out*, *tool missing*, *alerts off*, *read failed*, *unavailable*, *not checked*; *skipped here* for a source this machine skips), muted, and the tip lists every one in that order.
6. At least one `ok` → the facet rule over the `ok` facts. **`ok` needs positive evidence**: CI with zero runs on the default branch is *never ran*, not a pass (the `prReady` rule), and CI is the grey dot only when every workflow's newest run passed or skipped (one cancelled or unknown beside a pass reads *1 cancelled*); Security is clean only if a security source answered; a bot that is configured but has opened nothing for 30 days is *silent*, not healthy.
7. Partial coverage is stated, never hidden: *Dependabot clean · npm audit never run*. A list that hit its page cap (`truncated`) prints its count as `100+`.

Release and Git counts are as old as the last fetch, and Maintenance never fetches (that is `autofetch.ts`'s job). Their facts carry `fetched_at`, the newest `FETCH_HEAD` mtime of the repo and its worktrees (each checkout writes its own), and the tip says *as of last fetch 3d ago*; past a week it drifts on its own.

## Cost classes: nothing runs until asked

Each source declares one `cost`, and **Rust enforces it**, not a convention at the call site.

| cost | may do | runs in a scan | runs on a click |
|---|---|---|---|
| `local` | read files, read-only `git` through `git_cmd` | yes | yes |
| `forge` | read the forge through the user's own CLI credential (`gh`, `glab`) | yes | yes |
| `public` | send data to a third-party public service (OSV.dev gets package names) | only if this machine opted in | yes, one-off |
| `tool` | execute a program in the project (`npm audit`, `cargo audit`, `trivy`) | **never** | yes |
| `remote` | touch the user's infrastructure (HTTP to `[deploy] urls`, TLS, ssh) | **never** | yes |

`maint_read` takes a `mode` (`scan` or `explicit`) and a `public` flag, and refuses anything its class does not permit with `notRun`; the TS-side `runnable()` is a convenience, not the guard. A `tool` source is in the class `<pm> outdated` is in, and follows its rules (`docs/dependencies.md`): on a click, through `run_capped`, never on a load path, and a non-zero exit with a report is findings. On Windows it starts through `cmd.exe /D /C`, since npm and pnpm are `.cmd` shims `CreateProcessW` cannot start, so `SysExec` refuses any argument cmd would read as syntax. A `public` source's manifest row carries `sends`, and every door to it says who receives what (`disclosure`): the Settings switch that lets a scan ask it, and the *Check with* row that asks it once.

**A scan is triggered only by a person:**

- **Fleet:** switching to the Maintenance view when the cache is empty or older than `MAINT_FRESH_MS` (10 min), or ⟳ (forced). Landing on Maintenance at boot (`cc-fleet-view` persisted, and nothing restored took the stage) counts as that switch: it paints the last session's scans from `cc-maint-scan`, whole, and `maintOnBoot` (called once by main.ts after the boot picks its stage, never from `openFleet`, which every exit from the stage runs) scans when any of them is older than the window. While a re-read is out, a card drawn from the earlier answer is dimmed (`stale`) and its sub says *refreshing · as of 3h ago*; a tab dims whole. Booting onto Activity, or onto a session, scans nothing. `openFleet`, `loadFleet`, `renderFleet` and `buildView` never reach `maintscan`'s scans (they read its cache only), because `openFleet` runs at boot and on every exit from the stage (`docs/dashboard.md`'s *a fleet-wide sweep is exactly the "nothing runs until you ask" rule*). Choosing the tab is the ask that buys the sweep.
- **Project dashboard:** the first switch to the Maintenance tab per open scans that one project (`loadMaint`, shaped like `loadBranches`), and so does an open that lands on the tab (a fleet card's name, a *Review*). `renderDash` and the tab's count read the cache only; an account switch re-asks through `reloadDashGh`.
- **Explicit buttons:** *Run npm audit*, *Check with OSV.dev*, *Check prod*. Each names what runs or what leaves the machine. Where they sit is *Offers are not findings* below.

A test reads the source of those four functions and fails if any of them reaches anything of `maintscan`'s or `maintui`'s beyond the cache reads it lists. Once anything was checked, a project with no answer (added since, or forgotten on an account switch) is drawn as an unread card, so the all-clear never speaks for it.

A scan asks `maint_read` for **every** detected source the machine does not skip, not only the ones `runnable` offers: for a class the scan may not run, Rust's gate answers `notRun` (or the result a click left, kept 24 h) without running anything, so no facet waits forever on a read nobody makes. `maint_detect` and `maint_read` share the six slots.

## Detection

`maint_detect(root)` reads the remote, the files and `.episko/episko.toml`, and spawns nothing beyond the git remote read `project_facts` already does (plus, with no `origin`, the `git remote` listing that finds the primary remote, so the forge and the trunk come from one remote). It is cached per root for 30 s, so `maint_read`'s own applicability check (a stale frontend list must not run a source that no longer applies) does not walk the tree once per source.

- **The forge is decided before files.** `.github/workflows/` means GitHub Actions on github.com and Forgejo Actions on Codeberg; Renovate runs on every forge. Order: the `[maintenance] forge` pin, then a known-host table (`github.com`, `gitlab.com`, `codeberg.org` → forgejo, `bitbucket.org`, `dev.azure.com`/`*.visualstudio.com`), then a host containing `gitlab`/`gitea`/`forgejo`, then `unknown`. No network probe: a self-hosted host that names nothing stays `unknown` until pinned, and the tip says how. `git::split_remote` is already `pub(crate)`; `ssh_hostname` becomes it. The forge's `path` is everything after the host, not two segments: GitLab subgroups are `group/sub/repo`.
- **Files are probed, never executed**: a fixed list of paths at depth ≤ 2 under `SKIP_DIRS`, where a trailing `/` means a non-empty directory and `file#key` means a key inside a JSON file (`package.json#renovate`). The list is the union of the manifest's `detect` entries. An entry holding a `/` or starting with `.` is anchored at the root (GitHub reads `.github/workflows/` there and nowhere else); a bare name (`Jenkinsfile`, `Cargo.lock`) is also looked for one directory down, never inside a dot directory or `SKIP_DIRS`.
- **The git sources detect `.git`**, which is how a folder that is not a repo gets *not a git repository* rather than a Git cell that cannot answer. `[maintenance] off` and `sources` are applied in detection too, so `maint_read` refuses a source the file switched off (`unsupported`, *switched off in .episko/episko.toml*) and an off facet carries no markers.
- **Worktrees collapse to the repo root.** Facts are keyed by `repoRoot ?? path` (as `loadFleet` keys heads); a card is one per project.

## The manifest: `src/maintmanifest.json`

One checked-in file read by both sides, the `providers/manifest.json` precedent: Rust via `include_str!`, TS via `resolveJsonModule`. It sits flat in `src/` because the comment, IPC and sync gates do not recurse.

```jsonc
{
  "sources": {
    "github-actions": { "facet": "ci", "label": "GitHub Actions", "cost": "forge",
                        "forge": ["github"], "detect": [".github/workflows/"],
                        "sees": ["ci.default-branch", "ci.per-workflow", "ci.failing-since"],
                        "blind": ["ci.other-branches"] },
    "git-tags":       { "facet": "release", "label": "git tags", "cost": "local",
                        "forge": [], "detect": [], "sees": ["rel.unreleased", "rel.last"] }
  },
  "markers": [
    { "facet": "ci", "label": "Woodpecker", "detect": [".woodpecker.yml", ".woodpecker.yaml", ".woodpecker/"] }
  ],
  "bots": [
    { "id": "renovate", "logins": ["renovate[bot]", "app/renovate", "renovate-bot"],
      "branch": "renovate/", "dashboard": "Dependency Dashboard",
      "config": ["renovate.json", "renovate.json5", ".github/renovate.json", ".github/renovate.json5",
                 ".gitlab/renovate.json", ".renovaterc", ".renovaterc.json", "package.json#renovate"] }
  ]
}
```

- `facets` lists the seven in card order, each with its label and its *none* phrase (*no CI*, *no update bot*), so both sides phrase step 3 of `facetCell` from one place.
- `needs` (optional) names the config a source reads and that must be set before it applies: `sarif-files` has `"needs": ["sarif"]`, so a project that names no SARIF file has no such source and its Security cell can still say *no security source*; `http-probe` has `"needs": ["deploy.urls"]`, an address in `[deploy]`. The keys are a closed list (`NEEDS`, read by `needs_met`: `MaintConfig::has` for `[maintenance]`'s, the detection's `[deploy]` for `deploy.urls`), and `Manifest::check` refuses any other.
- `forge` restricts a source or a marker to the forges it can talk to; empty means any, and a list of `!x` entries means any forge but those (never mixed with plain ones), so a marker that steps aside for a GitHub-only source cannot silently miss a forge added later. An empty `detect` means "applies whenever the forge matches", so a marker needs at least one of the two or it would claim every project. A marker label may hold `{host}` (*CI on {host}*), filled from the remote.
- Rust parses the file with `deny_unknown_fields` and `Manifest::check` refuses it at load (the `providers/manifest.json` precedent): the seven facets in order, source ids equal to `SOURCES`, kebab-case ids, known forge ids, relative `detect` paths, every capability in `MAINT_CAPS`, and a complete `bots` row. A field the manifest does not define (an `argv`) fails the build's tests.
- `settings` (optional, a forge source of one forge only) is the https page that switches the source on, `{path}` the repository's: the three GitHub security sources name `security_analysis`. `settingsUrl` fills it only for an `off` coverage on a forge the source talks to, never for a pinned host the template does not name, and only for a path that is one `owner/repo`; so the link is data like the label, and `maint.ts` names no vendor.
- `queue` (optional, a work source only) says the dashboard's Today queue lists that source's issues and pull requests (`github-work`: the queue reads the slug `gh` is handed), so the Work board's counts open it (`WorkRow.queue`); a project whose work another source read keeps plain numbers.
- `sends` (required on a `public` source, refused on any other) is what leaves the machine, as a phrase: `disclosure` makes it the sentence *OSV.dev receives the name and version of every package in this project's lockfiles. Nothing else leaves this machine.*, which the Settings switch takes as its hint and the *Check with* row as its detail.
- `sees`/`blind` are a **closed capability vocabulary** (`MAINT_CAPS`). TS's `capsOf()` throws on an unknown one and Rust mirrors the list, the `providerCapabilities` rule: a misspelt capability must fail, not quietly drop a line from the coverage card.
- `bots` is the update-bot table `deps::bot_of` reads (it replaced a closed match and its dead TS twin `isBotPr`). A login matches with `[bot]` and `app/` ignored, since one App spells itself both ways. `[maintenance] bots` adds logins, which join Renovate's row (self-hosted Renovate); a closed match silently files their PRs on the human Open-work board. Every bot has a `<id>-prs` source, and a marker that stands in for one off its forges detects exactly its `config` files.
- **Only the compiled-in manifest defines what runs.** No argv, binary or authenticated URL ever comes from `.episko/episko.toml`: a committed table may select, disable and parameterise built-in ids, so a teammate's commit cannot make your Episko run a binary.

## Wire types

Rust, `#[serde(rename_all = "camelCase")]`, tagged enums:

```rust
#[serde(tag = "state")] enum Coverage { Ok, Off { reason }, NoAccess { reason, fix: Option<String> },
    NoTool { tool, fix: Option<String> }, Unsupported { reason }, NotRun, Error { reason } }

struct SourceReport { source: String, facet: Option<Facet>, cost: Option<Cost>, coverage: Coverage, // None: an id the manifest does not know
    at: Option<u64>,      // unix secs the read finished; a cache hit keeps the original
    truncated: bool,      // a list hit its page cap: counts are floors
    gaps: Vec<String>,    // honest partial support: "yarn.lock not read"
    facts: Option<Facts> } // Some only when coverage is Ok

#[serde(tag = "kind")] enum Facts {
    CiRuns     { branch: String, runs: Vec<CiRun> },          // default branch only, newest first, ≤ 50
    Advisories { items: Vec<Advisory> },
    UpdatePrs  { bot: String, configured: bool, prs: Vec<UpdatePr>, dashboard: Option<u64> },
    Release    { trunk: Option<String>, tag: Option<String>, tag_at: Option<u64>, since: u32,
                 oldest_unreleased_at: Option<u64>, tags_seen: u32, fetched_at: Option<u64> },
    Releases   { latest: Option<ForgeRelease>, count: u32 },
    Changelog  { unreleased: Option<u32>, latest: Option<String>, latest_at: Option<u64> }, // None: no Unreleased section
    Hygiene    { trunk: Option<String>, unpushed: Option<u32>, local_only: Vec<String>, merged: Vec<String>,
                 gone: Vec<String>, branches: Vec<BranchAge>, worktrees: Vec<WtAge>, fetched_at: Option<u64> },
    Work       { issues: u32, prs: u32, review_requested: Option<u32> },
    Probes     { items: Vec<Probe> },
    Runtimes   { items: Vec<Runtime> } }

struct CiRun    { workflow, status /* pass|fail|running|cancelled|skip|neutral|unknown */, raw, sha, at, url }
struct Advisory { id, aliases: Vec<String>, kind /* dependency|code|secret|config */, pkg, ecosystem,
                  version, severity /* critical|high|medium|low|unknown */, raw_severity, summary,
                  fixed, location, url, tool }
struct Probe    { name, url, code: Option<u16>, ms: Option<u32>, cert_not_after: Option<u64>, err: Option<String> }
struct Runtime  { product /* the list's id: nodejs */, name /* node */, declared, cycle: Option<String> /* None: unlisted */,
                  eol: Option<Eol> /* untagged: unix secs, or a bare true/false */, latest, newest, file, url: Option<String> }
struct UpdatePr { number, title, url, branch, draft, at: Option<u64>, checks: CiStatus }
struct ForgeRelease { tag, name, at: Option<u64>, url: Option<String> }

struct Forge     { kind /* github|gitlab|forgejo|gitea|bitbucket|azure|unknown|none */, host: Option<String>,
                   path: Option<String>, by /* pin|table|name|none */ }   // none: no remote at all
struct Marker    { facet, label, found: Vec<String> }                   // found: the paths that matched
struct Detection { repo_root, forge: Forge, sources: Vec<String>, markers: Vec<Marker>,
                   config: MaintConfig /* incl. readable: bool */, deploy: Option<DeployConfig> }   // deploy: `[deploy]`, unsafe values dropped
```

- `Forge.by` says how the kind was decided, so a tip can say *pin it in `[maintenance] forge`* exactly when nothing else could tell. The host stays as the remote spells it: an ssh alias resolves for the decision and is shown as written. Where an API is asked, when that is not the host as written, is kept as `api` (`#[serde(skip)]`, never on the wire), and `api_host()` is where `glab --hostname` points, since glab stores its credentials per real host: an alias's resolution when the alias is a bare name or only its resolution is in the host table (a dotted host whose ssh goes to an IP or a separate ssh endpoint stays the web host), and an http(s) remote's host *with* its port when that is not the scheme's own (glab keys a login by `host:port`).
- `Changelog` is its own kind because an *Unreleased* section is neither a tag nor a published release. Its entries are top-level bullets (`-`, `*`, and this repo's `+ ~ !`), with prose and no bullet counting as one.

- **One CI vocabulary.** `maint_ci::norm_status(raw)` is the only map from a vendor's status to `CiRun.status` (case-blind; `check_status(status, verdict)` reads a run's status until it completes). GitLab's words joined it in slice 9 (`failed`, `canceled`/`canceling`, `created`, `preparing`, `waiting_for_*`, `running` and `scheduled` as running, and `manual` as `neutral`: a pipeline held at a blocking manual job, typically a deploy gate, has failed nothing and runs nothing, so it is neither activity nor a pass, and the CI cell's tip names the raw word); none is a word GitHub sends, so no pinned verdict moved. `review::normalise_check` (the review's five words) and `deps::roll_checks` (the rollup's buckets) are projections of it, and agree: `cancelled` and `stale` (GitHub stopped waiting, no verdict) fail, `neutral` passes the rollup as GitHub's merge rule has it, and a word nobody taught us is `unknown`, which both read as pending, never as a pass or a failure. Today's outcomes were pinned first in `testdata/maint/check-verdicts.json`; a `*Was` field marks each verdict that changed, and each is in the CHANGELOG.
- **`Advisory.id` is generic** (GHSA, CVE, OSV, RUSTSEC, a scanner's rule id) and `aliases` carries the rest, so `mergeAdvisories` folds Dependabot, OSV and `cargo audit` reporting one CVE into one row at the worst severity. Names match case-blind (`cve-` meets `CVE-`), and a row keeps one spelling of each. A `code`, `secret` or `config` finding is keyed by its id **and its `location`**: a rule firing in two files is two findings, while GitHub code scanning and a CodeQL SARIF file reporting one place are one. The row's `key` is that identity. A card line is not a row: `findings` folds every row of one kind into one line (*One line per kind* below), and the tab's detail cards may still list the rows.
- **The wire is pinned by a fixture.** `wire_fixture_is_current` (cargo) serialises a fixed report covering every `Coverage` and `Facts` variant and compares it with `test/fixtures/maint-wire.json`; `test/maint.test.ts` reads the same file and asserts `narrowMaint` accepts it and every `state`/`kind` is in the TS unions. Regenerate with `MAINT_WIRE_WRITE=1 cargo test`. A renamed field fails on both sides.
- **`narrowMaint` narrows rather than trusts**: a report of the wrong shape becomes an `error` coverage for that source alone.

```rust
struct Ctx<'a> { root: &'a str, cfg: &'a MaintConfig, forge: &'a Forge, account: Option<&'a str>, force: bool }   // force reaches deps.rs's shared caches
struct SourceDef { id: &'static str, read: fn(&Ctx, &dyn Exec) -> Result<Read, Coverage> }
struct Read { facts: Facts, truncated: bool, gaps: Vec<String> }   // a Facts kind outside the source's facet is an `error`

trait Exec: Sync {
    fn gh(&self, root: &str, account: Option<&str>, args: &[&str]) -> Result<String, String>;
    fn glab(&self, root: &str, args: &[&str]) -> Result<String, String>;
    fn tool(&self, root: &str, bin: &str, args: &[&str], secs: u64) -> Result<Output, String>;
    fn http(&self, req: &HttpReq) -> Result<HttpResp, String>;   // absolute curl path
    fn ssh(&self, alias: &str, script: &str, secs: u64) -> Result<Output, String>;
    fn on_path(&self, bin: &str) -> bool;
}
```

- **`Exec` is the only side-effect seam**, in the inline `maint::exec` module. `Output` is maint's own (`code`, `stdout`, `stderr`) so `FakeExec` can build one. Until the tool and ssh adapters call the rest of it, that module carries the one `dead_code` allow (`gh` is called since slice 4, `glab` since slice 9, `http` since slice 11, `tool` since slice 12), and `ENV_TOKENS` is empty until an adapter needs a token. `HttpReq.report` is a probe: curl sends nothing, throws the body away (`-o` to the null device) and prints `-w '%{json}\n%{certs}'`, which comes back as the body; a transfer that failed is still a report, since `%{json}` carries `exitcode` and `errormsg`. `SysExec` wraps `github::gh`, `forge::glab`, `deps::run_capped`, `platform::sys_command` + `augmented_path`, and the absolute curl paths `telemetry.rs` already uses (a GUI app's PATH is stripped). Tests use `FakeExec`, which answers argv prefixes from recorded output in `src-tauri/testdata/maint/` and records every call (a report as `curl <url> --report`, a POST as `curl <url> --data <body>`); `exiting(code, stderr)` gives every `tool` an exit and `without(bins)` takes bins off its PATH. Local git sources go through git.rs and are tested against `testutil::git` repos instead.
- **`TRUSTED_BINS` per cost class** is enforced inside `SysExec::tool`: `forge` may reach `gh`/`glab`, `tool` the audit binaries, `remote` `curl`/`ssh`. Argv is always an array; a value from data is a whole element and is refused when it starts with `-` or holds whitespace (`ssh_hostname`'s rule). A `tool` binary is resolved to an absolute file on the augmented PATH's absolute folders (`resolve_bin`) and that file is spawned, never the bare name: cmd.exe, and a bare name on Windows, look in the current folder first, which is the project, so a cloned repository's `npm.cmd` would otherwise run in npm's place. The child's PATH carries only those absolute folders (a relative or empty entry is the project) and it also gets `NoDefaultCurrentDirectoryInExePath=1`, so a shim's own `node` lookup skips the project too, and `noTool` is that same resolution failing. Two tools read the project before they read the lockfile, and each is pinned from outside it: on Windows npm gets `npm_config_prefix` set to its own shim's folder (`npm.cmd` runs `<prefix>\node_modules\npm\bin\npm-cli.js` when one exists, and a project `.npmrc` may name the prefix; env outranks it), and pnpm gets `--config.ignore-pnpmfile=true --config.manage-package-manager-versions=false` (`PNPM_SAFE`), since it loads `.pnpmfile.cjs` and switches to `packageManager`'s version, and only a CLI flag outranks a `pnpm-workspace.yaml` asking for either. Both are executed in tests against the real tool when it is installed.
- **Env tokens go on curl's stdin** (`-H @-`), never in argv, and only names on a fixed allowlist are read. An absent one is `noAccess` *token not visible to Episko*, never *not configured*: a Finder-launched app gets none of `~/.zshrc`'s exports.
- **Reads degrade, writes fail loudly.** `read` never panics into the IPC layer; a failing source never erases another's report (the `dep_report` rule).

**Registry contract tests** (cargo) run over every `SOURCES` row, so a new adapter inherits them:

- manifest source ids == `SOURCES` ids, unique and kebab-case; every facet has a source, a marker or a *none* phrase;
- a `FakeExec` answering `Err`, `""` and `"<html>"` never yields `Coverage::Ok`;
- `read`'s `Facts` kind belongs to the source's facet;
- in `mode: scan`, a counting `FakeExec` records zero calls for every `tool`/`remote` source and for `public` without the flag;
- every call a source makes uses only bins trusted for its cost.

## Advisory sweep

*Does this advisory affect any of my projects?* The Security tab of the fleet carries one box: paste a CVE, GHSA, RUSTSEC or other OSV id, an advisory page's URL, `name@range` (`lodash@<4.17.21`, `@scope/pkg@^1.2`, `left-pad@*` for every version) or `ecosystem:name range` (`npm:next >=15.0.0 <15.5.6`, `cargo:smallvec <1.6.1`). Nothing runs until the person submits, the sweep is never part of a scan, and its runs are kept in memory for the session only (`maintscan`'s `sweeps`, at most six, newest first): no `cc-` key, no `localStorage`.

- **Two passes, the deterministic one first.** `sweep_advisory` (`maint_sweep.rs`) parses the query (`parse_query`: an id only for a known scheme prefix, so `left-pad` is never looked up; junk is refused with what would do) and resolves an id to its record at `api.osv.dev/v1/vulns/<id>` through the absolute curl as a `public` read. It is an explicit click, so it needs no per-machine opt-in, and the box says beside it what leaves the machine: **the id, and nothing else**. A record that names no package (a CVE converted from NVD often carries only a commit range) follows up to two of its aliases, GitHub's first, and those ids are all that is sent; `asked` lists every one. A package and range is built locally and sends nothing; with no ecosystem it is asked of every ecosystem `lockfile.rs` reads (npm and crates.io). A bare version typed there means that version in either: crates.io is not one of `deps.ts`'s caret-by-default ecosystems, since a sweep's range is a person's, not a manifest's. A record's own `versions` list is capped at 2000, and `versionsCut` says so: a version missing from a cut list is unsure.
- **Rust reads facts, TypeScript decides.** `sweep_match(roots, packages)` reads every project's lockfiles with `lockfile.rs` (read, never run, the same parsers `osv` uses) and answers per project the copies of each asked package (`found`: version and lockfile), the copies from git, a tarball, a path or another registry (`unpinned`, now named by `lockfile.rs` rather than only counted), a path or link copy (a `Cargo.lock` package with no source, a pnpm `link:`, a `package-lock.json` link: the project's own crate or package, or a vendored or `[patch]`ed copy, which a lockfile cannot tell apart) as unpinned too, the lockfiles read, and what might hold a copy and was not read (`unread`: a lockfile that failed or whose format version is not read, `yarn.lock`, `poetry.lock`, `go.sum` and the other lockfiles no parser exists for, or a manifest of any ecosystem — `package.json`, `Cargo.toml`, `pyproject.toml`, `requirements*.txt`, `go.mod`, `Gemfile`, `composer.json`, `pom.xml`, `build.gradle`, a `.csproj` — with no lockfile of its ecosystem in its folder or any above it), each with its ecosystem. Files are found at any depth through the project's index (`files::index_of`, the explorer's), plus `probe`'s root-and-one-level look for an ignored one; past 200 such files, or a cut index, every asked ecosystem gets an unread line, so a long list never reads as *not using*. npm names match exactly; crates.io and PyPI names fold case and `-`/`_`. npm names match exactly; crates.io and PyPI names fold case and `-`/`_`.
- **The verdict** (`sweepVerdict` in `maint.ts`, over `deps.ts`'s narrow `satisfies`): each OSV range run (`introduced` opens one, `fixed` or `last_affected` closes it; Rust splits the events) becomes a range string (`spanRange`), and each installed copy is placed (`placeVersion`). **affected** when any copy is inside a run (its evidence the lockfile, the version and the run; its fix the run's `fixed`, *bump → 4.17.21*, or *no fix published*); else **unsure** when anything could not be placed — a range shape `satisfies` answers `null` for, a version it cannot parse, a commit (`GIT`) range, a git or path copy, an unread lockfile of the advisory's ecosystem, a record naming no package — never a guess either way; else **patched** (*patched* when at or past a fix, *not in range* below where it was introduced); else **not using**, naming the lockfiles read. An unread lockfile of another ecosystem says nothing about this one. There is a row for every root asked: one `sweep_match` answered nothing for (cut at 500, or narrowed away) is unsure (*its lockfiles were not read*), and a failed read is the run's error, never an empty table. Rows are worst first, then by path.
- **The board** (`sweepHtml` in `maintview.ts`, fleet only, after the advisories): the advisory (id and aliases linking to its page, severity, every affected package and range), a verdicts table (project, verdict, evidence, fix) with the projects not using it named in one line below, and its doors, all `data-mtsweep`: *Patch* on an affected row prefills an agent with `sweepBrief` (the copies in range as advisory rows through the same `patchLines` the Patch verb uses, with `deps.ts`'s compatibility and verify blocks), never sent; *Check with an agent* on an unsure row runs `sweep_check`, `deploy::propose_toml`'s restricted headless agent (`claude -p --restricted --tools Read,Glob,Grep`, in that project) asked `sweepPrompt`, whose fenced `toml` block (`verdict` affected / not-affected / unsure, `evidence`) `parse_check` reads; the answer is shown in the row and changes nothing, so a row stays *unsure* and *Brief N agents* counts only the deterministic hits; *Brief N agents* prefills one agent per affected project; *Copy report* copies `sweepReport` through Tauri's clipboard; a recent run's chip shows it again. Enter in the box submits (`maintKey`), and the fleet's `paint` keeps the box's text, caret and focus across a repaint. Narrowed to one project, the table shows that project's row, and *Brief* and *Copy report* carry its root (`data-mtroot`) so they act on that row alone.

## `[deploy]` and `[maintenance]`

```toml
[deploy]                                  # committed; proposed by an agent, written only after Apply
host = "prod-1"                           # an ssh alias; nothing connects until a click
compose = ["api", "worker"]
urls = { app = "https://app.example.com", api = "https://api.example.com/health" }
sentry = "acme/api"                       # org/project; the token is never in the file
version_url = "https://api.example.com/version"

[maintenance]                             # optional; absent = detect everything
forge = "gitlab"                          # for a self-hosted host whose name says nothing
off = ["prod", "github-secret-scanning"]  # a facet ("not tracked") or a source id
sources = { ci = ["woodpecker"] }         # restrict a facet to these ids; detection must still agree
bots = ["acme-renovate"]                  # self-hosted update-bot logins
trunk = "dev"
tag_pattern = "v*"                        # glob_match (`*` only; ?, [ ] and \ are refused); which tags are releases
sarif = ["reports/*.sarif"]
[maintenance.params]                      # values a built-in source needs; a URL must be http(s)
woodpecker_server = "https://ci.example.com"
[maintenance.thresholds]                  # raw data; clampMaint applies them over the defaults
unreleased_commits = 30
unreleased_days = 21
stale_branch_days = 30
cert_warn_days = 21
bot_silent_days = 30                      # a configured bot whose newest open PR is older is *silent*
bot_pr_backlog = 5                        # open update PRs that count as a pile
fetch_stale_days = 7                      # release and git counts drift once the last fetch is older
eol_warn_days = 90                        # a runtime whose cycle ends sooner is drifting
```

- A red default branch is broken from its first failing run, however young: CI has no threshold. Every threshold is `MAINT_DEFAULTS` until the file says otherwise, and a stale fetch lifts a Git or Release cell to drifting with its own `git:fetch` finding, so amber always has a line under it.
- Read forgivingly, by every owner's own `RawFile` that ignores other tables. A file that exists and does not parse is `readable: false`, and the tips say *episko.toml unreadable* rather than quietly applying defaults (`ProtectList.readable`'s rule).
- `[deploy]` is written only by `write_deploy`: `toml_edit` read-modify-write, tmp file then rename, only the keys whose value changed replaced (a hand-written value keeps its comment), compared against the table as the reader saw it, so a key whose only difference is a value the read dropped is left alone, and a rewritten `urls` or `compose` carries the dropped entries over (the proposal never saw them, so it cannot mean to remove them), no write when unchanged (the file is committed and churn lands in a diff), the table removed when empty, `create` gating a new file. A missing file with `create: false` is refused with `NO_FILE`, and `proposeDeploy` then asks *Create .episko/episko.toml?* before writing it: Apply answered for the table, not for a new file. Reads drop an unsafe value (an alias or service that is not one argv word, a non-http address, a `sentry` that is not `org/project`); the write refuses it and names it. A write drops Rust's detection for the project (`forget_detection`) but no report, so the rescan that follows reads the new table and nothing else. It is reached from the Apply dialog after `propose_deploy` (the restricted headless agent `propose_stack` uses, through the shared `propose_toml`; `checkDeploy` refuses non-http URLs, a `-`-leading alias and a bad `org/project`), or by hand through *Open file*.
- `[maintenance]` is set up the same way, for four keys only: `trunk`, `tag_pattern`, `sarif` and `bots` (`MaintSetup`, `deny_unknown_fields`). `off`, `sources`, `forge`, the thresholds and the params change what is read or judged and stay a person's, so the proposal lists any other key it set as left out, and the writer never sees one. `write_maint` goes through `edit_toml` with `write_deploy`'s rules (only a changed key replaced, no write when unchanged, `create` gating a new file), but a write that changed the file drops the project's cached reports too, the bots' PR read with them: every one of the four keys feeds a cached read, and a rescan that served the old reason would make Apply look like it did nothing. It refuses a trunk that is not one argv word, holds `* ? [ ] \ ~ ^ :` or is a revision expression (`@{`, `..`, `@`, `HEAD`), a tag pattern with any wildcard but `*`, a SARIF path that leaves the project (`sarif_inside`, the rule `sarif-files` walks by) and a bot that is not a login, naming each. A table left with only `[maintenance.thresholds]` keeps no empty header, unless a comment rides on it, and an unchanged setup never touches the header. `maintPrompt` shows the agent the current keys and every Coverage reason a key would answer (*no remote, so no default branch: set [maintenance] trunk*), and `maintCfgText` names each current value the proposal changes or removes. The doors: *Propose with an agent* and *Open file* on the project tab's Coverage rows whose reason names a key (`setupKeyOf`; a read whose gap names one, as `git-local`'s merged branches without a trunk, says so on its row), and the project settings panel's **Maintenance** row beside **Where it runs**. `test/fixtures/maint-checks.json` is run by both `keep_setup` and `checkMaintCfg`; its `key` lines are `checkMaintCfg`'s alone (Rust names the key in `unknown`, and serde refuses it at write). maint.test.ts holds `SETUP_KEYS` to maint.rs's.
- `deploy_config` and `write_deploy` resolve a project path to the repo root (`root_key`) exactly as detection does, so a subfolder project or a worktree reads and writes the main checkout's file, the one the Runs-on card reads. A Re-check shows the agent the current table verbatim (`deployToml`), since a value it is not shown is a value it drops and Apply would remove; the dialog lists each current value the proposal removes or changes (`deployLosses`). `test/fixtures/deploy-checks.json` is one case table run through both `keep` and `checkDeploy`, so the two refusals cannot drift.
- A round-trip test writes `[deploy]` and `[maintenance]` into a file holding every other table and runs `parse_stack`, `parse_protect`, `parse_allow` and `parse_health_policy` over it.
- Config lives in git and never in sync: it changes what runs (`docs/stack.md`).

## Adding an adapter

1. Add a row to `src/maintmanifest.json` (facet, label, cost, forge, detect, sees, blind); if it was a marker, delete the marker.
2. Write `read_x(ctx, ex) -> Result<Read, Coverage>` in the facet's `maint_*.rs`, using only `Exec`. Map stderr to a coverage with a `fix` when one exists. A non-zero exit from an audit tool is data (`run_capped`'s rule).
3. Add the `SourceDef` row. A new binary goes into `TRUSTED_BINS` under its cost class, and a new `tool` binary is a design review item.
4. Record a real output in `src-tauri/testdata/maint/` and test the parser and `read` over `FakeExec`. The registry contract tests apply on their own.
5. Only if the facts fit no existing `Facts` kind: add the variant on both sides, regenerate the wire fixture, teach `facetCell`/`findings`, test it. Otherwise nothing changes in TypeScript.
6. A new capability goes into `MAINT_CAPS` and its Rust mirror; a new env token onto the allowlist.
7. Add a row to the adapter table below: what it reads, its cost, its credential, what leaves the machine.

Every other row is a marker in `src/maintmanifest.json` until its slice promotes it. `sarif-files` and `http-probe` have none: they read what config names rather than what is on disk. **`forge-commit-status` detects the config files of the CIs that report back** (`Jenkinsfile`, `.circleci/config.yml`, `.woodpecker*`…) rather than nothing: an empty `detect` would make it a source on every GitHub repo, and step 3's *no CI* could never be drawn. On GitHub those files are its, so their markers say `"forge": ["!github"]`; `no_marker_claims_a_file_a_source_reads` holds a marker off any file a source of its facet reads on the same forge.

Every GitLab read runs as whoever glab holds for that host (glab has no per-call account the way `GH_TOKEN` gives gh one, so `Ctx.account` is not passed). `classify_glab` turns its failures into coverages, every fix `glab auth login --hostname <host>`: glab missing is `noTool` with its install link, signed out (a 401, an invalid token, glab asking for `glab auth login`) is `noTool`, a 404 (GitLab answers a project an account may not see exactly like one that does not exist) or a 403 (`insufficient_scope` included) is `noAccess`, a rate limit and anything else is `error` verbatim. A pinned GitLab host is read, unlike a pinned GitHub one: a self-hosted GitLab is the reason the pin exists. That is why `forge::glab` removes `GITLAB_TOKEN`, `GITLAB_ACCESS_TOKEN`, `OAUTH_TOKEN` and glab's CI variables from its child: glab sends an env token to whatever `--hostname` names, ahead of its per-host login, and the host comes from the repository.

Every GitHub read runs as the project's pinned account (`Ctx.account`, the `gh` `account` the frontend passes). `gh_coverage` turns its failures into coverages: gh missing or signed out is `noTool` with its fix, a 404 / *could not resolve to a repository* / any 403 but a rate limit (SAML SSO and fine-grained tokens included, checked before `classify`, whose *token* match would say `gh auth login`) is `noAccess` naming who asked, a pin gh no longer holds is `noAccess` with `gh auth login`, anything else is `error` verbatim. A host pinned as `github` that is not github.com is `unsupported`, since the same `owner/repo` there could be someone else's; a pin the host table agrees with (an ssh alias that resolves to github.com) is reported `by: table`, so it is read.

The trunk is `[maintenance] trunk` when it resolves to a commit (a typo is reported, never replaced by `main`), else the primary remote's default branch (origin, else the first remote; the forge is read from the same one). There is no local guess: a repo with no remote and no pinned trunk gets the tip *set [maintenance] trunk*.

Markers in v1: Woodpecker, CircleCI, Azure Pipelines, Jenkins and Drone off GitHub (on GitHub `forge-commit-status` reads their files), Forgejo/Gitea Actions, Bitbucket Pipelines, Snyk, Depfu, Mend, and *CI on <host>* for workflows on an `unknown` forge. Later, behind the same shape: ssh host facts (one `ssh -o BatchMode=yes` round trip per host), Sentry, GitLab MRs for Renovate, Gitea/Forgejo via token, pip-audit, osv-scanner, trivy, grype, snyk, govulncheck.
