# The project explorer (⌘P)

> Rules and their reasons, compressed. Trust the code over the docs when they disagree, and fix the doc in the same commit.

The app's **third list of files**, and the only one that shows a file nothing has happened to. The other two answer narrower questions and neither can answer "where is that file": the **working set** (`git_diffstat` → `wpeekHtml` → the peek) knows only what changed, and the **Context card** (`files.ts`, fed by the hook stream) knows only what one agent has been into. The explorer is the superset, which is the design: *Changed* and *Touched* are **chips over the same rows**, not two more screens, so a path is described the same way wherever you meet it. A fourth surface that lists files joins that join rather than sitting beside it.

- **One index feeds both modes.** Empty field → browse the folder in the breadcrumb; typed → find across the project. `browseRows` derives folders from the same flat path list `findRows` searches, so the two cannot disagree about what a project contains and stepping into a folder costs no round trip. The alternative (a `read_dir` per folder) is a second source of truth that differs constantly — an ignored build directory is on disk and not in the project.
- **`git ls-files --cached --others --exclude-standard` is the whole index for a repo.** Tracked plus untracked-but-not-ignored, in one process, with `.gitignore` honoured by the tool that owns it. **This is why the app has no ignore parser and must not grow one.** `-z`, because a path may contain anything but NUL. `--cached` lists a conflicted path once per stage, so the result is sorted and deduped.
- **A folder that is not a repo still works**, via a bounded walk (`MAX_DEPTH`, no dot-directories, no `node_modules`/`target`/…, `MAX_FILES`). It reports `truncated` and the overlay says so: a file list that silently stops lies about what a project holds. Symlinked directories are not descended — the one way a bounded walk becomes unbounded.
- **Nothing watches the filesystem, and this is not the feature that changes that.** The index is read on open and cached per root for `CACHE_MS`; the marks are never cached (one cheap `git_changed` per open). The app's rule holds: the hook stream is the trigger, git is the authority (docs/worktrees.md).
- **One matcher in the app.** `fuzzy`/`frecScore` come from `palette.ts`, so a file you keep opening ranks like a command you keep running and ⌘K's ordering and the explorer's cannot drift. Equal scores tie-break on the path, so rows never reshuffle between keystrokes.
- **A touch mark survives the trip from an absolute hook path.** `relPath` maps `file_path` back to the index's spelling, case-insensitively (macOS and Windows both hand back paths whose case does not match what was typed, and a mismatch drops every mark rather than misplacing one). Anything outside the project is dropped, which is the common case and not an error: agents read files in `$HOME`, in dependencies, in sibling checkouts. `touchIndex` climbs the same read → edited → created ladder the Context card does, so a second session re-reading what the first created cannot demote it.
- **What ↵ does is decided in one place** (`rowAction`) and shown in the footer *before* the key is pressed. A changed file opens **its diff in the peek**; anything else is handed to the OS. The rule: **the app shows you changes, the OS shows you contents** — which is what lets the explorer stay read-only without needing a viewer of its own. `openDiff`'s third argument unfolds that one file and leaves the rest of the working set folded under it as context; a path that has stopped being changed between the two reads just leaves the index as it was (a race, not an error).
- **Keys**: `↵` act · `⌘↵` reveal · `⌥↵` copy path · `⌫` up a folder (only when the field is empty — inside a query that is editing text) · `esc` close. Copy goes through `tauri-plugin-clipboard-manager`, never `navigator.clipboard`.
- **`mod+p` is the default binding** and it joins `KEY_ACTIONS` like every other one, so Settings › Keys can rebind or clear it and the footer sheet and palette hints read it from there. `keys.test.ts` fails if it is not also in a `KEY_GROUPS` section.

**Non-goals, in the order the temptations arrive.** It is an overlay: it opens, does one thing, dies on Escape — no pane, no persistent tree, no expansion state to remember, and browse is a navigator (one folder behind a breadcrumb), not a tree. It is read-only: no create, rename, delete, stage or discard, because agents change files and git records it. It never reads a file's contents — a preview wants search-in-file, then jump-to-line, then editing, and each is reasonable once the first exists.
